# x402 adapter declaration, v0

**Status.** Informational. This file re-declares x402 under the same five items as
[`lightning-v0.md`](lightning-v0.md), for this plugin. The checks themselves are declared in the
Agent Action Capsule repository's `spec/adapters/x402-v0.md`, with its conformance vectors in
`vectors/adapters/x402/`. That declaration is authoritative for every check named below, and this
file repeats none of its detail.

## What this plugin does with x402 today

Nothing yet: mesh-llm's paid inference settles over Lightning only. No host event carries an x402
object, so this plugin holds none. `settlement_check` reads only the plugin's Lightning
settlement records: it reports no x402 settlement and counts none.

## The five items

| Item | x402 |
|---|---|
| (a) Native object | `PaymentPayload` (`PAYMENT-SIGNATURE` header, base64-decoded octets), `SettlementResponse` (`PAYMENT-RESPONSE`), and the receipt from the Offer and Receipt Extension. These are the registered wrapped object types `x402.payment-payload`, `x402.settle-response` and `x402.receipt` |
| (b) Issuers | payer (EIP-3009 authorization signature), facilitator (settlement response, not signed), payee (receipt, signed). Addresses resolve to parties only through the relying party's trust policy |
| (c) Verification method | EIP-712 recovery of the payer over the authorization, with the domain taken from the relying party's policy and never from transmitted values; the receipt's signature check; a transaction lookup on the chain the response names |
| (d) Predicate | X1 to X5 of `x402-v0` §8. The settlement predicate is X3: the payer's authorization was executed on the named chain, in the named transaction, inside its validity window. None of them is `delivered` |
| (e) Per-property results | as `x402-v0` §7 defines them. Finality is the chain lookup (`settlement_onchain`, §6.4), which is an independent source, not the facilitator's statement |

## Band

When this plugin holds x402 settlements, each exchange's band will follow the same rule as
[`lightning-v0.md`](lightning-v0.md#band): `currency` is the amount's `assetCode`, and `decade` is
`floor(log10(value / 10^assetScale))`, signed. One cent of USDC (`assetScale` 6) is `USDC`
decade -2. The currency is part of the band, and a band is never compared with another
currency's. An x402 settlement is on chain, so it can fill the public-ledger count that Lightning
leaves `NOT_CHECKED`.
